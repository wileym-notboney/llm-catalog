# LLM Catalog — Grooming to Best Practice

_Plan written 2026-10-10. Status: ready to execute. Produced via the planner skill (designed, quality-reviewed, one finding fixed, structurally validated)._

## Problem

Groom the self-hosted, LAN-only LLM Feed Dashboard toward best practice **without reorganizing its sound architecture**. `feed/`, `serve.py`, and `app/src/` are clean and stay exactly where they are. The grooming is four moves on a solid base:

1. **One bundler.** Drop the vestigial Vite toolchain; make Parcel the single bundler.
2. **Dependency trim.** `app/src` imports only `react` + `react-dom`; cut the ~30 never-imported runtime deps and the Vite-only devDeps.
3. **Exposure recipe.** Document `tailscale serve` as the LAN/remote exposure path — `serve.py` stays bound to `127.0.0.1`, no auth code added.
4. **ADR layer.** Introduce `decisions/` so `AGENTS.md` stays the lean always-loaded index and the "why" lives in on-demand records.

## Non-negotiable constraints (from AGENTS.md + the Tailscale decision)

- Runtime stays **stdlib-only Python**; `pytest` is dev-only.
- `serve.py` keeps binding **`127.0.0.1`**; exposure is via `tailscale serve` only.
- Only `app/dist` and `/items.json` are served; `state.json`/`attempts.json` stay 404.
- Model catalog stays **bundled, not served** (`app/src/models.json` inlined into `app/dist/index.html`) — a deliberate security boundary.
- After any UI/dep change, `cd app && pnpm run bundle` must regenerate `app/dist/index.html` and it must still render; `tests/test_models_catalog.py` stays green.
- `FIRECRAWL_API_KEY` never written to file/log/`data/`; `.env` never edited.
- `CHANGELOG.md` kept current (one line per commit); commits `type(scope): description`.

**Out of scope:** moving/renaming `feed/`, `serve.py`, `app/src/`, `tests/`; touching the scraper regex, retention, paid-attempt, or writer-lock logic; adding runtime deps or a router; the local pre-commit pytest gate (deferred, pending a separate decision); CI.

## Rejected alternatives

- **Bind 0.0.0.0 + trust LAN** — no auth; the exact exposure Tailscale avoids.
- **0.0.0.0 + HTTP basic auth in serve.py** — breaks stdlib-only; forces a credential-in-file story.
- **Reverse proxy (Caddy/nginx)** — infra outside the repo; Tailscale already runs in the homelab.
- **Keep both bundlers** — two toolchains for no gain; Vite never makes the shipped artifact.
- **Keep Vite, drop Parcel** — the inlined single-file artifact comes from Parcel + html-inline; redoing it on Vite is rework on the one thing that must keep rendering.
- **Wholesale directory reorganization** — structure is already clean; pure churn/risk, out of scope.
- **Add CI (GitHub Actions)** — private/LAN project; a local gate was considered and deferred.

## Risks & mitigations

- **R-001 — trim changes the built artifact.** Mitigation: `pnpm install` then `pnpm run bundle`; confirm both routes render and the `app/dist` diff is limited to expected content. Trim only never-imported packages.
- **R-002 — Parcel dev server clobbers the committed `app/dist`.** (Parcel defaults output to `dist/`.) Mitigation: pin `--dist-dir .bundle` (git-ignored); verify `git status` stays clean on `app/dist` after `pnpm run dev`.
- **R-003 — dropping Vite type refs breaks type-check/lint.** Mitigation: remove `vite/client` from `tsconfig.app.json`, delete `tsconfig.node.json`, then `pnpm test` + `pnpm run lint` green.
- **R-004 — Tailscale recipe over-exposes.** Mitigation: document `tailscale serve` (tailnet-private) only; keep the no-auth warning; never document `tailscale funnel` (public).
